# 创意图片工坊：项目实施方案与验收清单

版本：v0.1 · 2026-10-29

状态：开发前设计，尚未实现或运行验证。依据用户提供的《小影科技2027校招-全栈开发笔试题》HTML 正文 R-01～R-14 及四张参考图整理。原题是需求基准；本文中具体名称、接口、参数和布局尺寸是实施选择，可在开发中调整并记录。

## 1. 产品范围与完成标准

用户浏览模板，按要求上传图片，提交任务，观察后台三个阶段的执行情况，继续创建其他任务，刷新或重新进入后查看个人历史和结果。

首版提供三个分类、六个模板，覆盖一张和两张图片：旅行明信片、城市海报、宠物封面、宠物纪念卡、双人拼贴、旅行对照卡。种子数据、封面、示例输入和模拟结果均随项目交付；不得依赖运行时外链。最终素材来源及许可记录在 README。结果区明确标注“模拟生成示例”，不宣称处理了用户图片。

完成标准是：容器启动后，无需修改源码即可演示成功、三个阶段分别失败、多任务并存、刷新恢复、查询异常恢复及个人数据隔离，并通过关键测试。

不加入真实 AI、视频处理、积分、会员、支付、模板管理后台、任务删除／重做／下载、复杂账号系统、消息队列和集群。这些能力不是原题必需项。服务重启后自动续跑也不在首版范围。

### 页面路由

| 路由 | 内容与行为 |
| --- | --- |
| `/` | 模板广场；顶部品牌、模板广场、我的作品、访客标识；分类筛选；卡片展示标题、封面、所需图片数 |
| `/templates/[id]` | 左侧模板信息、独立上传位和提交按钮；右侧当前模板的个人任务历史，未完成任务优先展示 |
| `/history` | 所有模板的个人记录；未完成任务区与分页历史区；展示创建时间、模板名、阶段、结果或原因 |

制作页桌面端左栏约 360～420px、右栏自适应；窄屏改为上下排列。列表网格随宽度调整列数，避免固定六列导致小屏不可用。整体深灰底、圆角卡片、高对比文字、黄绿色主按钮；失败和成功同时用文字／图标表达，不能只靠颜色。

详情页右侧沿用参考图的历史区域，另设全局历史页方便跨模板查看。模板页只跟踪当前模板任务；离开后后台继续执行，回到相关页面时从服务端重新恢复。

### 主要交互

1. 分类放在 URL 查询参数中，刷新后可保持筛选；模板不存在时显示返回广场入口。
2. 每个上传位支持选择、预览、替换、移除；展示 JPEG/PNG、单文件不超过 5 MiB、准确所需数量。
3. 上传位有 empty、uploading、ready、error 四种状态。替换时废弃旧请求；通过上传位版本号防止旧响应覆盖新选择。移除预览时释放 object URL。
4. 素材未就绪或提交请求尚未结束时禁用提交；点击时同步锁定，避免连续点击产生重复请求。
5. Java 返回任务 ID 后，在右侧立即插入任务卡，结束“提交中”。已上传素材可以保留，允许用户主动发起另一个任务。
6. 等待时显示“排队中”；处理中显示真实阶段名称；失败显示阶段和原因；成功显示结果缩略图，点击打开预览弹窗。
7. 上传失败可重新选取；查询失败提供“恢复查询”；任务执行失败不提供重做按钮。三类错误的文案和操作分开。
8. 所有页面覆盖加载、空数据、请求失败；成功结果图片加载失败时显示“图片暂不可用”，不修改任务状态。
9. 上传控件有标签，图标按钮有名称；保留键盘焦点；预览弹窗支持 Escape、焦点约束与关闭后焦点返回。

## 3. 技术与部署结构

采用单仓库：`frontend/`、`backend/`、`docs/`、`compose.yaml`、`.github/workflows/ci.yml`。不引入微服务。

浏览器访问 Next.js，`/api/*` 经同源转发交给 Java。Next.js 只承担页面和透明转发，模板、身份、素材、任务、历史全部由 Java 处理。必须转发 Cookie、Set-Cookie、状态码和文件流，禁止缓存个人接口及任务响应。

```text
浏览器 → Next.js 页面 / 同源 API 转发 → Spring Boot → MySQL
                                         │
                                         ├─ 有界线程池 → 三阶段执行器
                                         └─ 持久化文件卷（上传和结果）
```

建议基线为 Node.js 22、Next.js App Router、与所选 Next.js 匹配的 React、TypeScript；Java 21、Spring Boot 3.5.x、MyBatis Starter 3.0.x、MySQL 8.4。前端使用 CSS Modules 和集中封装的请求／轮询 Hook，避免引入不必要的全局状态库。测试采用前端组件测试与后端单元／MySQL 集成测试。

这里锁定的是技术系列，不是已验证的依赖清单。M0 初始化时检查可用稳定补丁、安全更新和 peer dependencies，写入精确依赖版本、锁文件、Maven 配置及镜像标签，再通过容器构建确认兼容性，不在交付配置中使用 `latest`。

已核对的官方依据：Next.js 安装文档列出 Node.js 最低 20.9，支持直接使用 ESLint；Spring Boot 3.5 支持 Java 21；MyBatis Starter 3.0 对应 Spring Boot 3.2～3.5。

## 4. 身份与素材访问

采用匿名访客会话，避免额外注册流程。首次进入页面显式调用身份初始化接口，Java 创建访客和高熵随机令牌；数据库只保存令牌摘要，浏览器使用 HttpOnly、SameSite=Lax Cookie。会话建议有效期 30 天；HTTPS 部署启用 Secure，本地 HTTP 演示使用单独配置。

前端先完成一次会话初始化，再发其他请求，避免并发初始化产生多个身份。有效 Cookie 刷新后保持身份；接口不接受客户端指定的 ownerId。新建身份是显式 POST 行为，其他接口发现会话无效时返回 401，前端取消旧请求、清空旧身份缓存，再重新初始化。

查询任务、上传素材引用、素材预览和结果读取都按当前访客校验归属；未找到或无权限统一返回 404。私有图片由 Java 鉴权后读取，不把整个文件目录映射为公开静态目录。公开模板封面与私有上传素材分开存放。

写操作校验同源 Origin，跨域调用默认不开放。界面显示“当前为本机访客，清除浏览器 Cookie 后无法找回记录”。不同浏览器或独立隐私会话用于演示隔离；普通同浏览器标签页共享身份。匿名方案不支持跨设备找回，需在 README 如实记录。

## 5. 数据模型

所有时间由服务端生成，接口返回 UTC ISO 8601，前端按本地时间展示。ID 对外使用字符串；任务和资源使用不可预测标识。私有资源授权仍以归属检查为准。

| 表 | 主要字段及约束 |
| --- | --- |
| `visitor` | id、display_name、created_at |
| `visitor_session` | token_hash（唯一）、visitor_id、expires_at |
| `template` | id、category、title、description、cover_path、required_image_count、accepted_mime_types、max_file_size_bytes、mock_result_path、sort_order |
| `asset` | id、owner_id、original_name、storage_key、detected_mime、size_bytes、created_at；仅在文件持久化成功后插入可用记录 |
| `creation_task` | id、owner_id、template_id、template_title_snapshot、status、current_stage、failed_stage、error_code、error_message、result_storage_key、simulation_json、version、created_at、started_at、finished_at、updated_at |
| `task_asset` | task_id、asset_id、slot_index；任务与位置唯一，保留输入顺序 |
| `task_stage` | task_id、stage、status、started_at、finished_at、error_code、error_message；任务与阶段唯一 |

阶段记录从 PENDING 开始，依次进入 RUNNING、SUCCEEDED 或 FAILED；失败后的阶段标为 SKIPPED。整体任务状态只有 QUEUED、RUNNING、SUCCEEDED、FAILED。

主要索引：任务 `(owner_id, created_at, id)`、`(owner_id, status, created_at)`、`(owner_id, template_id, created_at)`；素材 owner_id；会话 token_hash。模板及示例数据随数据库版本脚本初始化，避免每次启动重复插入。关系使用外键或等价约束，更新阶段记录和任务快照在同一短事务中完成。

上传先检查实际字节大小、文件签名及图片可解码性，不能只信扩展名或请求 MIME；限制像素尺寸以避免异常大图。使用服务端生成的 storage_key，用户文件名只作展示。文件写入失败或数据库插入失败时清理本次临时文件。文件系统和数据库不具备跨系统原子事务，崩溃后可能遗留孤立文件，首版记录此限制。

## 6. API 契约草案

接口统一位于 `/api`。成功返回直接 JSON；错误采用 `{code, message, fieldErrors?, requestId}`。列表限制 pageSize 最大 50；所有私有响应设置 `Cache-Control: no-store`。

| 方法与路径 | 请求 | 响应及语义 |
| --- | --- | --- |
| POST `/session` | 无 | 创建或复用访客会话，返回访客 id、展示名、expiresAt |
| GET `/categories` | 无 | 分类列表 |
| GET `/templates` | category 可选 | 模板卡片列表 |
| GET `/templates/{id}` | 无 | 标题、描述、封面、上传数量／类型／大小限制 |
| POST `/assets` | multipart file | 201：assetId、previewUrl、mimeType、sizeBytes |
| GET `/assets/{id}/content` | 无 | 当前访客的图片字节 |
| POST `/tasks` | templateId、按位置排列的 assetIds | 202：完整初始任务快照，包括 taskId、status、currentStage、version |
| GET `/tasks/{id}` | 无 | 任务快照及三个阶段记录 |
| GET `/tasks` | templateId、cursor、pageSize 可选 | 倒序个人历史 items、nextCursor |
| GET `/tasks/active` | templateId 可选 | 当前范围内所有未结束任务摘要，仅用于进入页面后的恢复 |
| POST `/tasks/status-query` | taskIds，最多 50 个 | 批量只读查询；返回任务快照，不触发执行 |
| GET `/tasks/{id}/result` | 无 | 成功任务的结果图片，检查归属及成功状态 |

静态 `/tasks/active` 与 `/tasks/{id}` 的映射应显式区分。批量查询必须逐项校验归属；不泄露其他访客的任务。单任务及批量返回同一结构，列表卡片不另建状态口径。

任务快照示例：

```json
{
  "taskId": "task_example",
  "templateId": "travel-postcard",
  "templateTitle": "旅行明信片",
  "status": "RUNNING",
  "currentStage": "GENERATE",
  "failedStage": null,
  "error": null,
  "resultUrl": null,
  "version": 3,
  "createdAt": "2026-10-29T08:00:00Z",
  "updatedAt": "2026-10-29T08:00:02Z"
}
```

建议错误映射：400 参数无效，401 会话失效，404 不存在或不属于当前访客，413 文件过大，415 类型不支持，422 素材数量／归属／可用性不符合模板要求，500 未预期错误。后台制作失败是任务数据，查询仍返回 200 和 FAILED；不能用 HTTP 500 表示“模拟生成失败”。

提交请求超时属于“是否受理未知”：前端提示先刷新个人记录，不自动重发 POST。首版不承诺服务端提交幂等，防重复点击不等同于网络重试幂等。

## 7. 后台任务状态机与执行边界

```text
QUEUED / 无阶段
  → RUNNING / CHECK_ASSETS
  → RUNNING / GENERATE
  → RUNNING / PACKAGE_RESULT
  → SUCCEEDED / PACKAGE_RESULT

任一运行阶段失败 → FAILED，保存 failedStage 与原因，后续阶段 SKIPPED
调度拒绝 → FAILED，errorCode=EXECUTOR_REJECTED，failedStage=null
```

1. 同步校验模板存在、素材数量、类型、大小、归属及已落盘状态；事务中创建任务、输入关联、三个阶段记录，状态 QUEUED。
2. 事务提交完成后，将 taskId 提交到有界线程池。建议演示默认 2 个工作线程、队列 20 个，可配置。禁止使用 CallerRunsPolicy，防止队列满时请求线程执行整条制作流程。
3. 入队拒绝时用新事务记录调度失败；返回已创建的任务快照。202 只表示任务记录已受理，不保证最终制作成功。
4. Worker 通过条件更新将 QUEUED 改为 RUNNING；只有更新成功的执行者继续。每个阶段开始及结束各进行短事务更新，模拟等待期间不持有数据库事务或连接。
5. CHECK_ASSETS 再次检查关联素材是否仍可读取；GENERATE 执行可控延迟并选定模板预置结果；PACKAGE_RESULT 将预置结果复制到任务专属目录，确认可读，再写入结果路径及成功状态。
6. 阶段异常统一终止流水线，记录安全可读的错误信息及阶段，不把堆栈返回前端。使用任务 ID、阶段、耗时关联服务端日志。
7. 每次任务变更增加 version；SQL 更新限定原状态，终态不允许回退。所有 GET 和 status-query 都只读数据库，不推进阶段。

应用只运行一个后台实例。正常关闭允许在限定时间内等待任务完成；强制重启不承诺续跑。建议启动时把遗留 QUEUED/RUNNING 标记为 FAILED / EXECUTION_INTERRUPTED，说明“服务中断，任务未完成”，防止前端无限等待；这属于中断状态收敛，不是自动恢复执行。执行阶段已开始时保留其 failedStage，否则为 null。数据库不可用时不能保证错误即时落库，应记录日志并在数据库恢复后的重启检查中收敛。

## 8. 模拟控制与前端轮询

模拟默认耗时建议 1 秒、8 秒、1 秒。开发 profile 下允许 POST `/tasks` 增加 `simulation`，包括 `failAt` 与各阶段 `delayMs`；任务创建时保存配置快照，不修改运行中任务。failAt 为 NONE、CHECK_ASSETS、GENERATE、PACKAGE_RESULT，非指定阶段正常执行。延迟限制在 0～60000ms。关闭开发模拟开关时拒绝请求中的覆盖配置。

README 提供在浏览器同源上下文或携带独立测试 Cookie 的请求示例；正式页面不暴露开发参数，不提供无归属校验的管理端点。

前端集中维护：

- `tasksById`：服务端任务快照，以 taskId 隔离。
- `pendingIds`：当前页面范围内需要跟踪的任务。
- `queryErrorsById`：查询异常，绝不写入任务的 status/error。
- `sessionGeneration`、页面 scope、请求序号：用于丢弃旧身份、旧页面和乱序响应。

进入页面先完成会话初始化，再获取历史和 active 列表，合并去重。单独读取 active 可防止分页第一页之外的旧任务漏跟踪。初始加载失败时提供重试，不能把“未知”当成“没有待处理任务”。

默认每次查询完成后等待 2 秒再查下一轮，不采用可能重叠的 setInterval。按未完成 taskId 分组，每批最多 50 个；完成一个就从 pendingIds 移除，没有任务时停止定时器。终态历史不会被自动重复查询。

暂时查询失败保留最后快照，显示更新异常，下一次可延后到 5 秒并提供手动恢复入口；会话失效则终止本轮。请求需要超时和 AbortController。离开页面、切换模板或身份时取消定时器和请求，并通过 generation 校验忽略仍晚到的响应。任务快照只接受更高或相同 version 的一致更新，旧 RUNNING 不得覆盖新 SUCCEEDED。

关键测试不以覆盖率数字代替行为：后端对三个阶段分别注入失败，断言后续方法未调用；模拟等待器可替换，单元测试不真实睡眠。数据库约束和 MyBatis 映射使用容器内真实 MySQL 验证，不能仅依赖 H2 推断兼容性。

前端使用可控网络响应和假计时器验证多个任务、网络故障后恢复、终态停止、切换身份晚响应、上传替换晚响应、旧版本任务快照被忽略。容器中的测试、构建和人工演示分别记录结果；“未验证”必须与“未实现”区分。

## 10. 实施顺序与交付

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| M0 工程基础 | 精确依赖、目录、Dockerfile、Compose、数据库版本脚本、CI 框架 | 容器构建通过，Java 健康检查及模板接口可用 |
| M1 最小闭环 | 访客、单模板上传、任务创建、三阶段执行、结果读取 | 页面提交后最终能预览结果，数据库可追溯 |
| M2 状态可靠性 | 多任务、指定阶段失败、轮询清理、异常恢复、刷新与分页恢复 | 核心后端／前端行为测试通过 |
| M3 页面与素材 | 六模板、分类、双栏、历史、小屏、键盘与各种反馈 | 参考布局及基本可用性检查通过 |
| M4 验收交付 | CI 完整执行、干净环境容器启动、README、演示说明、素材来源 | R-01～R-14 有明确实现与验证状态 |

不据保存 HTML 中的倒计时推算真实截止时间；交付日期以用户与招聘方约定为准。开发开始后记录各阶段实际投入，再填写 README，不提前虚构工时。

Compose 持久化 MySQL 与文件目录，健康检查通过后启动依赖服务。构建、安装、测试与应用运行都提供容器执行路径。CI 中 lint、类型检查、测试、构建是独立步骤，不能假定 build 自动完成全部检查；执行失败必须使流水线失败。

交付应支持 `docker compose up --build`；另提供容器内前端检查和后端 `mvn verify` 的精确命令。数据库初始化采用可重复运行的版本迁移机制。重新启动不得清空已有数据。

部署说明覆盖配置、端口、数据卷、健康检查和日志；回滚说明覆盖保留上个镜像／源码版本、升级前备份数据库及文件卷、数据库迁移兼容性。只回滚应用不能保证撤销数据库结构变化，不把删除卷作为普通回滚步骤。

最终 README 必含：技术版本、启动和测试命令、接口、数据库、模拟控制、身份隔离、任务状态、重启边界、完成／未完成／未验证项、已知限制、实际投入、AI 工作流及修正实例、复用来源、部署回滚步骤；仓库交付注明验收 commit。

## 11. 已确定的取舍

优先完成可解释的单体闭环。匿名会话不提供账号找回；轮询不追求毫秒级实时；本地文件卷不解决多实例共享；有界线程池不保证跨进程持久化执行；不自动重试创建任务；预置结果不表达真实 AI 效果。任何超出这些边界的能力，应在核心验收完成后再决定是否扩展。

当前文档已足够作为 M0～M4 的开发输入；下一步是初始化工程并锁定实际可构建的版本组合。
